# Fixture capture

Regenerates `../../src/test/fixtures/*.ts` — the journey tests' (#169) fixture
data — from a real backend. Built for the initial capture (2026-07-22, ER-C
prod + the UTM test VM) and kept here because the same workflow will be needed
again once #172 (FastAPI rewrite) changes response shapes.

**Nothing here runs automatically — every step is a manual, reviewed command.**

## Safety rules

- **`capture.sh` is GET-only.** Safe to point at production. It never mutates
  anything.
- **`capture-share.sh` creates and deletes a real share.** Only ever run it
  against a test stack (the UTM VM) — never production. It cleans up after
  itself (`DELETE` in a trap), but treat the target project/dataset as
  disposable regardless.
- **Never pass credentials as a command-line argument or paste them in chat.**
  Both scripts read `TOKEN_FILE`, a `chmod 600` file holding
  `base64(username:password)` (the same value the app stores in
  `sessionStorage` under `erc.auth` — see `api/auth.ts`). Create it with
  `printf`, not `echo`, so it never lands in shell history as a literal:
  ```bash
  printf '%s' 'dXNlcjpwYXNz' > ~/.erc-capture-token && chmod 600 ~/.erc-capture-token
  ```
  Delete it when you're done — it's a real, reusable Unix password in
  reversible encoding.
- **`raw/` and `scrubbed/` are gitignored on purpose.** `raw/` holds real
  identities; it must never be committed. Regenerate it, don't archive it.

## Workflow

1. **Capture** (read-only):
   ```bash
   BASE_URL=https://er-c-data-mgmt.fz-juelich.de \
   TOKEN_FILE=~/.erc-capture-token \
     ./capture.sh <project-name> <browse-path> [more-browse-paths...]
   ```
   Writes `raw/{projects,project-details,users,shares}.json` and
   `raw/browse-N.json` per path given.

2. **(Optional) capture a real share**, against a **test stack only**:
   ```bash
   BASE_URL=http://localhost:5001 \
   TOKEN_FILE=~/.erc-vm-token \
     ./capture-share.sh <project-name> <dataset-name>
   ```
   Writes `raw/share-created.json` + `raw/shares-with-active.json`, then
   deletes the share it just created.

3. **Pick which projects to keep.** Edit `selected-projects.json` — a flat
   array of real project names from `raw/projects.json` to keep in the
   fixture. Pick for *variety* (member-count spread, name-length range, a
   numeric-UID owner if one exists), not volume — the fixtures exist to
   exercise shapes, not to mirror production at scale.

4. **Scrub**:
   ```bash
   node scrub.mjs
   ```
   Writes `scrubbed/*.json` and prints the full identity/name mapping to
   stdout. **Read this output.** It's a keyed pseudo-random substitution
   seeded per-string (not a fixed cipher like ROT13 — that decodes with one
   click on any public tool) that preserves length, case pattern, and
   punctuation/digit positions but replaces every real username, numeric UID,
   and project/folder name. Session/dataset names are deliberately **not**
   scrubbed — they're demo/test data ("create by hand", "testsession"), not
   identities.

   Before trusting the output, grep it for the real strings you captured — a
   `relpath` or a breadcrumb `full` path that only gets its last segment
   scrubbed is exactly the kind of leak that's easy to miss (this happened
   during the original capture; `scrubPath` splitting on every `/` segment is
   the fix).

5. **Write the fixture modules**:
   ```bash
   node write-fixtures.mjs
   ```
   Writes `../../src/test/fixtures/{projects,project,users,browse}.ts` from
   `scrubbed/*.json`. `share.ts` isn't generated by this step — if you ran
   `capture-share.sh`, adapt `scrubbed/share-created.json` into
   `fixtures/share.ts`'s `makeFixtureShare()` by hand (it's a small object).

6. **Diff and typecheck** before committing:
   ```bash
   git diff ../../src/test/fixtures/
   cd ../.. && npx tsc -b --noEmit && npm test
   ```

7. **Clean up**: `rm -rf raw scrubbed` (gitignored anyway, but don't leave real
   identities sitting on disk longer than needed).
